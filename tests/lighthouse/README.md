# Lighthouse: швидкість завантаження інтерфейсу (NFR-8)

**NFR-8:** інтерфейс завантажується не довше ніж за 2 с при стабільному з'єднанні.

## Запуск

Потрібні Node 18+, Google Chrome і запущений `docker compose` (фронтенд на `http://localhost:3000`).

```bash
node tests/lighthouse/run-lighthouse.mjs --runs 3 --label after
```

Скрипт проганяє сторінки каталогу, входу та реєстрації по 3 рази в мобільному режимі (Lighthouse імітує повільний 4G і вчетверо слабший процесор) і в десктопному, а потім бере медіану. Звіти (HTML + JSON) та підсумкова таблиця `summary.md` зберігаються в `tests/lighthouse/reports/<label>/`. Ця тека в git не потрапляє.

### Що змінилося порівняно з початковим станом

| | До | Після |
|---|---|---|
| Accessibility | 77–100 | 100 |
| SEO | 82 | 100 |
| Performance | 99–100 | 99–100 |
| Основний JS-бандл | 362 КБ (111 КБ gzip) | 334 КБ (107 КБ gzip) |
| Повторний візит | файли збірки щоразу завантажуються заново | кешуються на рік (`immutable`) |

Виправлення:

- **Ліниве завантаження** (`React.lazy`) адмінки, кабінету й відновлення пароля. Каталог, вхід і реєстрацію навмисно лишили в основному бандлі. Перший варіант робив лінивими й їх, але тоді LCP входу та реєстрації на мобільному погіршився з 1,51 до 1,73 с: при прямому заході на `/login` браузер спершу вантажив основний бандл і лише потім окремий файл сторінки.
- **Кешування:** `serve.json` (Docker) і `public/_headers` (Cloudflare Pages) задають `Cache-Control: public, max-age=31536000, immutable` для `/assets/*`. Імена цих файлів містять хеш вмісту, тож кеш ніколи не застаріває. `index.html` отримує `no-cache`, щоб нова версія підхоплювалася одразу.
- **Доступність:** `aria-label` для кнопки мобільного меню, пошуку й списку жанрів, прихований заголовок `h2` для правильного порядку заголовків, підкреслене посилання «Увійдіть тут».
- **SEO:** `lang="uk"`, `<meta name="description">`, зрозумілий `<title>`, справжній `robots.txt` (раніше на `/robots.txt` повертався `index.html`).

### Обмеження

- Майже весь основний бандл (~330 КБ) — це React, React Router і axios. Помітно зменшити його можна лише заміною бібліотек, що невиправдано для цього проєкту.
- LCP каталогу на мобільному (1,84 с) найближчий до межі. Його визначає запит каталогу: сітка книг з'являється лише після відповіді API. Заміри зроблені, коли каталог вантажив 100 книг одразу; тепер він вантажить по 20 (нескінченна прокрутка), тож час має зменшитись — повторно не вимірювали.
- Сторінки за авторизацією (кабінет, адмінка) Lighthouse без входу не вимірює. Час їхнього завантаження перевіряють E2E-тести.
